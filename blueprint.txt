BLUEPRINT / SERVER MODULES AND DATA MODEL

MODULE STRUCTURE

  app/
    main.c                         TCP listener and connection workers
  components/
    request_handler.c              protocol dispatch and banking operations
    request_handler.h              request-handler interface
    session_manager.c              login/session lifecycle
    session_manager.h               session interface
  storage/
    database.c                     table files, record locks, append IDs, WAL
    database.h                     database and transaction interface
  utils/
    common.h                       roles, limits, shared record structures
    socket_io.c                    socket request/response helper functions
    socket_io.h                    socket helper interface

data tables (database/)
  users.txt
  accounts.txt
  loans.txt
  transactions.txt
  feedback.txt

DATA RECORDS

User
  id: sequential user row ID
  role: CUSTOMER, EMPLOYEE, MANAGER, or ADMINISTRATOR
  username: unique text, max 49 characters
  password: demo-only plain text, max 49 characters

Account
  user_id: unique foreign key to users.txt; also the client-visible account number
  balance: integer cents
  active: whether customer operations are enabled
  row exists only for an actual account; staff without an account have no logical account row
  blank physical slots preserve direct user-ID byte-range locking without storing placeholder data

Loan
  id: sequential loan row ID
  customer_id: customer user ID
  amount: integer cents
  status: PENDING, ASSIGNED, APPROVED, or REJECTED
  employee_id: assigned employee ID, or zero

Transaction
  id: sequential transaction row ID
  customer_id: owner of the transaction
  amount: integer cents
  type: opening, deposit, withdrawal, transfer, or loan credit
  timestamp and details: printable text

Feedback
  id: sequential feedback row ID
  customer_id: submitting customer
  text: up to 255 characters

LOCKING AND TRANSACTION OBJECTS

DbTransaction holds the per-record locks and pending record images for one request. DbEntry identifies the table, record ID, lock mode, and changed value. fcntl locks cover only the fixed byte range for the selected record. Append locks allocate new IDs; the WAL/commit lock protects cross-table commit and recovery. Sessions are held in a process-local table and are not part of the persistent database.
