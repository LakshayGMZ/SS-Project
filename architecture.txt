TRANSACTION BOUNDARY
A single server request loads one consistent state while holding both synchronization locks. A financial operation mutates the in-memory snapshot and commits all affected records together with a temporary-file rewrite and rename. A failed validation does not write the snapshot. The file lock is held during the complete read-modify-write cycle to prevent lost updates from concurrent processes.
